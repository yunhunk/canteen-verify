> 需求：「公司可设置员工剩余核销次数」
> 环境：http://66.154.119.26（管理后台 :80 / 后端 127.0.0.1:3100 不对外）
> 状态：已上线并通过全量验证

---

## 一、做成了什么

### 三层配额模型

```
公司池  companies.remain_quota            ← 总量兜底，平台充值
  └─ 员工额度  employees.quota_total/quota_used   ← 公司分配给个人（本次新增）
       └─ 时段限次  verification_rules.per_employee_limit
```

核销时**双重扣减**：公司池与员工额度**同时扣**，任一不足都拒绝。

### 公司管理员怎么用

员工管理页新增「剩余次数」列，三种形态一眼可辨：

| 显示 | 含义 |
|---|---|
| `不限`（灰） | 公司未对该员工设限（默认，老数据保持此状态） |
| `5 / 5`（绿） | 剩余 5 次 / 总额度 5 次 |
| `0 / 5`（红） | 额度已用完 |

- 行内「**设置次数**」：弹窗里 `不限次数` 开关 + `核销次数` 数字框 + `清零已用` 勾选，
  并实时提示「该员工已核销 N 次，设置后剩余 M 次」
- 工具栏「**批量设置次数**」：勾选多人统一下发同一次数

### 员工侧（小程序）

- **核销码页**：二维码下方直显「剩余 X 次」/「剩余次数不限」，剩 ≤1 次变橙提醒
- **次数用完**时不出码，改为「🎫 核销次数已用完」+ 已用/额度 + 「反馈问题」入口
- **「我的」页**：新增「剩余核销次数」行；用完时给醒目提示卡

### 关键取舍

| 决策 | 理由 |
|---|---|
| `quota_total` 用 `NULL` 表示"不限制" | 老数据自动为 NULL → 老租户行为与上线前**完全一致**，可平滑灰度 |
| 剩余量不存列，用 `总额 - 已用` 现算 | 避免两个字段不同步 |
| 不做"追溯压缩"（额度调小不缩已用量） | 否则核销历史与计数对不上；想重发额度用「清零已用」 |
| 批量混入别家公司员工 → **整批 403** | 静默跳过会让管理员以为都设好了，等员工核销被拒才发现漏了 |
| 新增业务码 `2007`（与公司池不足 `2002` 分开） | 处置动作不同：2002 找平台充值，2007 找公司管理员加次数 |

冒烟新增第 15 节共 34 条断言，覆盖：

- 默认「不限」可通过 `null` 显式表达；缺参必须 400（`null` 与"不传"语义不同）
- 剩余次数 = 总额度 − 已用（现算）
- 三个员工端接口（`me` / `windows` / `qrcode`）都回传额度
- **真核销一次 → 员工已用 +1、剩余 −1**
- 额度用尽：发码被拒 **且核销也被拒**（返回 2007，不是 2001）
- 非法值：负数 / 小数 / 缺参 → 400
- 越权：跨公司 403、员工角色 403、未登录 401
- 批量设置落库复核；**混入外公司员工 → 403 且整批未生效**
- 设置额度写入操作日志

## 三、上线动作

1. **MySQL 加两列**（生产库不跑 `init.sql`，需手工 DDL）
   `ALTER TABLE employees ADD COLUMN quota_total INT NULL, ADD COLUMN quota_used INT NOT NULL DEFAULT 0`
   → 历史行自动 `NULL / 0`，5 名存量员工状态不变
2. **复位演示数据**（库被历次冒烟污染：公司 A 曾被停用、规则时段被改）
   → 先 `mysqldump` 备份到 `/opt/canteen/backups/`
3. **后端**：打包 → 校验包内容 → 上传解压 → `pm2 restart canteen-api`
   → 确认仍绑 `127.0.0.1:3100`，未暴露公网
4. **管理后台**：原地 `cp -a` 覆盖 `/opt/canteen/admin-web`
   （bind mount 绑的是目录 inode，`mv` 换目录会让容器继续指向旧 inode）
5. **CDP 真实浏览器验证**：平台 7 页 + 公司端员工额度页 + 设置弹窗

## 四、过程中排掉的坑

1. **CDP 复用同一个 profile 会连到上一轮的标签页**
   现象是「首页不跳登录页、0 个输入框」，看着像前端挂了。根因是 Edge 单实例把新进程
   转发给残留旧实例。改为每次用**唯一 profile 目录 + 唯一端口**，
   并把「固定 sleep」换成轮询等 `#/login`。**未杀任何 msedge 进程**（本机可能有用户自己的浏览器）。
2. **CDP 里用 `/设置次数/` 正则先命中了工具栏的「批量设置次数」**，只弹出"请先勾选员工"，
   被误判成弹窗打不开。改用精确文本匹配 + 追加控件级断言。
3. **导入 SQL 中文变乱码**：`docker exec -i mysql < x.sql` 少了 `--default-character-set=utf8mb4`，
   中文变 `ç¤ºä¾‹`，导致公司名匹配全失败（不报错，只在读取时暴露）。
4. **`PUT /api/company/rules/:id` 传 `{status:0}` 被 400 静默拦掉**（DTO 必填字段校验）
   → 状态变更一律走专用 `/:id/status` 接口。

以上均已沉淀进 skill。
