# 扫码核销 App · 交付说明

**交付物**：原生 Android 工程源码（`scan-app-android/`），核销员用手机摄像头扫员工动态核销码、联网核销、语音播报。与扫码枪/闸机共用同一条设备密钥通道，零账号体系。

---

## 一、为什么是"源码交付"而不是 APK

本机没有 JDK / Android SDK / Gradle（已实测确认），无法编译 APK。为保证交付质量，做了两层**不需要编译器也能做的验证**：

| 验证 | 结果 | 覆盖内容 |
|------|------|----------|
| 工程静态一致性检查（`check-android.js`） | **14/14 通过** | 42 个 XML 可解析、181 处 XML 资源引用、55 处 Kotlin 资源引用、12 处格式化字符串参数、Manifest 组件 ↔ Kotlin 文件、ViewBinding ↔ 布局、包声明 ↔ 目录结构 |
| 接口契约验证（`verify-api-contract.cjs`） | **55/55 通过** | 用 Node 等价复刻 App 网络层，对本地真实后端跑通：密钥校验、核销成功全字段、绑店优先、时段回传、全部失败码 |

编译前人工排除了 3 个静态检查覆盖不到的编译级问题：`<activity>` 上误用 View 属性 `keepScreenOn`、可空 `Int?` 传入 `putExtra` 的 `int` 重载、检查器自身的平衡括号缺陷。

**你唯一要做的一步**：装了 Android Studio 的电脑上打开工程 → Build APK（步骤见 `scan-app-android/README.md`）。

## 二、功能与界面

1. **绑定页**：输入平台发放的一次性设备密钥 → 探测校验（复用核销接口、不新增攻击面）→ 保存进入扫码
2. **扫码页**：CameraX 预览 + ML Kit 扫码（bundled 模型，离线可用）；扫到即震 + 立即停扫防重复提交；补光 / 前后镜头切换 / 手动输码（员工碎屏时用）
3. **结果页**：成功显示员工、餐标、剩余次数、**播报回显**（员工说没听清可直接对照），4 秒自动返回连扫；失败显示原因 + **该找谁**（2002 找平台充值 / 2007 找公司管理员加次数），不自动返回
4. **记录页**：本机 200 条核销记录，交班核对用

## 三、关键设计决策

- **语音直接念后端 `voiceText`**：金额去尾零、有无餐标都在服务端统一，客户端改口径不用发版。契约验证确认返回精确为 `核销成功，餐标15元`
- **扫到即停**：识别器上报一次后置门闩，杜绝一次扫码连发十几个请求
- **失败分类给行动建议**：`FailKindMapper` 把 2001/2002/2005/2006/2007 翻译成"下一步该做什么"，一线核销员不需要理解业务码
- **密钥失效当场处理**：核销收到 2006 → 清空本地绑定 → 弹窗引导重新绑定
- **必须联网**：行为与扫码枪完全一致，不做离线放行（避免"本地先放行、后端却拒了"的账目纠纷）
- **TTS 待播队列**：冷启动 TTS 初始化窗口内的第一次核销不会丢播报

## 四、上线清单

1. Android Studio 打开 `scan-app-android/`，Build APK（Gradle 首次同步需联网）
2. 管理后台「设备管理」为每台手机登记一台设备（建议按门店绑定），保存**仅显示一次**的密钥
3. 手机装 APK → 输入密钥绑定 → 扫员工核销码实测一次
4. 对账：核销记录在后台「核销记录/操作日志」可见；本机记录页仅辅助核对

**后端零改动**——App 使用的 `/api/device/verify` 是现有接口，本次契约验证还在本地后端实测通过（55/55）。

## 五、已知限制与后续

- **未经真机编译**：首次 Android Studio 构建如报依赖版本类错误，按 IDE 提示微调即可；业务代码经静态检查与契约验证，风险集中在 UI 层细节
- 当前明文 HTTP（`network_security_config` 已放行）；备案 HTTPS 域名后改一行配置收紧
- 核销失败无语音播报（与扫码枪行为一致，后端只返回成功播报文本）；如需失败语音，可基于 `FailKindMapper` 的分类补固定提示音
- 小程序端（员工出示码）不受本次改动影响
