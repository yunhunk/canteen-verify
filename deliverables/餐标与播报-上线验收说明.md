# 小程序首页剩余次数 + 公司餐标 + 核销机器播报 · 上线验收说明

**上线时间**：2026-09-23 22:5x
**环境**：`66.154.119.26`（Ubuntu 24.04 / MySQL 8 in Docker / pm2 + nginx）

---

## 一、这次做了什么

### 1. 小程序首页突出「剩余核销次数」

首页顶部新增一张额度卡，进门第一眼就能看到：

- **受限**：大字号显示剩余数字 + 「已用 5 / 共 20 次」
- **不限**：显示绿色「不限」+ 「公司未限制个人次数」
- **剩 ≤1 次**：数字变橙
- **已用完**：整卡变红 + 「次数已用完，请联系公司管理员」

「可核销时段」列表里每一行由原来的「每人 1 次」改为 **「今日还可 N 次」**，今日已用完的时段标灰并显示「今日次数已用完」——避免员工白跑一趟饭点。

核销码页与「我的」页也同步展示剩余次数与餐标。

### 2. 新增公司餐标（12 / 15 / 18 / 20 元四档）

餐标挂在**公司层级**（全公司统一一个标准），由公司管理员在新增的
**「公司设置」**页里选，平台管理员也能在「公司管理」里代设。

- 四档下拉 + **「不设置」**选项
- 页面底部有 **机器播报预览**：「核销成功，餐标15元」——所见即所得
- 有改动才允许点保存，保存后回到禁用态

档位**不写死**：后端 `MEAL_STANDARD_TIERS` 是单一来源，由 `GET /api/company/settings`
下发给前端；校验只做范围检查（`0 < 餐标 ≤ 1000`）。将来某家公司谈了个 13 元的餐标，
不用改代码就能设。

### 3. 核销机器语音播报

核销接口（`POST /api/device/verify`）在返回体里新增 `voiceText`：

```json
{
  "success": true,
  "employeeName": "张三",
  "mealStandard": 15,
  "voiceText": "核销成功，餐标15元",
  "remainQuota": 99
}
```

机器的固件读 `voiceText` 做 TTS 即可，**客户端零改造**。
公司未设餐标时退化为 `"核销成功"`。

金额在服务端去尾零（`15.00 → 15`），否则 TTS 会念成「餐标十五点零零元」。

## 二、关键设计取舍

| 决策 | 理由 |
|---|---|
| **餐标不参与扣减** | 一次核销永远扣 1 次。餐标只影响展示与播报，账目口径不变（冒烟里有断言：设餐标后公司池仍只减 1） |
| **`NULL` = 未设置** | 加列用 `NULL` 而非 `0`，历史公司自动是「未设餐标」，上线前后行为完全一致，零数据回填 |
| **播报文案由服务端拼** | 机器固件各式各样，让它自己判断「有没有餐标、要不要去尾零」等于把业务规则复制到每台机器上 |
| **餐标传 `0` 视为清除** | 0 元没有业务含义，与其存个 0 让播报变成「餐标0元」，不如统一按未设置处理 |
| **餐标工具独立成 util** | 公司端设置、平台端编辑、核销播报、员工端展示四处都要用，放 service 里会让核销模块为了一个纯函数去 import 一个 service，迟早绕成循环依赖 |

## 三、接口变化

| 接口 | 变化 |
|---|---|
| `GET /api/company/settings` | **新增**（公司端）。返回餐标 + 档位 + 上限 |
| `PUT /api/company/settings/meal-standard` | **新增**（公司端）。`null` = 清除；不传字段 = 400 |
| `PUT /api/platform/companies/:id` | 扩展 `mealStandard`（平台可代设/清除） |
| `GET /api/platform/companies` | 列表带出 `mealStandard` |
| `POST /api/device/verify` | 核销成功返回新增 `mealStandard` / `voiceText` |
| `GET /api/employee/me` | 新增 `mealStandard` / `mealStandardText` |
| `GET /api/employee/windows` | 每个时段新增 `usedToday` / `remainToday`；顶层新增餐标 |

`remainToday` 为 `null` 表示该时段不限次（后端 `limit = 0`）。

## 五、上线动作

1. **MySQL 加列**（生产不跑 `init.sql`，手工 DDL，带 `--default-character-set=utf8mb4`）
   ```sql
   ALTER TABLE `companies`
     ADD COLUMN `meal_standard` DECIMAL(10,2) NULL
     COMMENT '餐标（元），NULL=未设置；仅展示与语音播报，不参与扣减'
     AFTER `remain_quota`;
   ```
   加完核对历史行 → 全部 `NULL` ✅
2. 备份 + 复位演示数据（历次冒烟会留下「时间戳命名的测试公司」和被停用的种子公司）
3. 后端打包 → **校验包内容**（`meal-standard.js` / `settings/meal-standard` / `voiceText`）
   → 上传解压 → `pm2 restart canteen-api --update-env`
4. 管理后台产物 → **原地 `cp -a` 覆盖** `/opt/canteen/admin-web`
   （bind mount 绑的是目录 inode，`mv` 换目录会让容器看不到新文件）
5. 服务器复跑全量 + 浏览器验证
6. 复位演示数据，餐标设为 15 元作为演示初始态

**安全边界**：后端仍只绑 `127.0.0.1:3100`（未暴露公网），公网只开放 nginx :80。

## 六、过程中修掉的三个真实缺陷

1. **服务启动即崩**——`SetMealStandardDto` 写在控制器之后，触发 TDZ
   （`design:paramtypes` 在类定义前求值）。`tsc --noEmit` 完全看不出来，
   本地跑第一次全链路就抓到了。
2. **「清除餐标」被 400 静默拦掉**——`@IsNumber()` 把 `null` 判为非法，
   前端以为清空成功了实际没清。改用 `@ValidateIf(o => o.x !== null)`，
   既让 `null`（有效输入）通过，又让「没传字段」仍然 400。
3. **浏览器断言假失败**——写死「点 15 元 → 断言保存按钮变可点」，
   第二次运行时库里已经是 15，`dirty` 为 false，按钮保持禁用。
   改为动态挑一个与当前值不同的档位。

其余踩坑（远程命令 `$()` 被本地展开、decimal 在 MySQL 返回字符串、
`el-select` 清空产物不确定）已全部写进 skill。

## 七、遗留

- **核销失败时不播报**（本次需求只要求成功播报）。若机器需要失败语音，
  可在全局异常过滤器里按业务码补 `voiceText`（加字段，向后兼容）。
- 小程序需用微信开发者工具手动上传（绑本人微信账号）；真机测试需 HTTPS 备案域名，
  裸 IP 会被微信拦截。
