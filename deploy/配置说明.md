# 配置说明

> 本文档是整个系统的**配置总账**：每个端有哪些配置文件、每一项是什么意思、
> 改了会有什么影响、日常变更去哪里改。新同事接手或换服务器时照这份走即可。

---

## 一、配置全景图

| 端 | 配置文件 | 是否进 git | 说明 |
|---|---|---|---|
| 后端（生产） | `deploy/.env` | ❌ **禁止** | 全部真实密钥，只存在于部署机 |
| 后端（模板） | `deploy/.env.example` | ✅ | 占位值 + 逐项标注，新机器照它填 |
| 后端（本地开发） | `backend/.env` | ❌ | 本地连库/端口，可配 `LOCAL_MODE=1` 走 SQLite 零依赖 |
| 员工小程序 | `miniprogram/utils/request.js` | ✅ | 后端地址（BASE_URL） |
| 员工小程序 | `miniprogram/project.config.json` | ✅ | 小程序 AppID |
| 微信官方后台 | mp.weixin.qq.com | —（线上） | 服务器域名白名单、AppSecret |
| 扫码 App | `scan-app-android/app/build.gradle.kts` | ✅ | 后端地址（编译期注入 `API_BASE`） |
| 扫码 App | `app/src/main/res/xml/network_security_config.xml` | ✅ | 明文流量策略 |
| 管理后台 | **无需配置** | — | 前端用相对路径 `/api`，跟浏览器地址自动走 |
| 服务器 nginx | `/opt/canteen/nginx.conf`（容器挂载） | —（服务器上） | 反代规则 + HTTPS 证书路径 |

**核心原则**：所有敏感值只放在 `.env`（不进 git），代码仓库里只有模板和结构。

## 二、后端 `.env` 变量总表（生产）

来源：`cp deploy/.env.example deploy/.env` 后填值。标记：★必改 / ◇可选 / 免改。

### 1. 数据库

| 变量 | 标记 | 是什么 | 怎么配 | 改动影响 |
|---|---|---|---|---|
| `MYSQL_ROOT_PASSWORD` | ★ | MySQL root 密码，仅首次建库用 | 自编强密码（≥16 位） | 仅空数据卷首次启动生效；之后改它需进容器 `ALTER USER` |
| `DB_USER` / `DB_PASSWORD` | ★ | 后端程序连库的业务账号 | 自编；首次启动自动创建并授权 | 在 .env 改密码**不会**自动同步数据库，要进容器 `ALTER USER` |
| `DB_NAME` | 免改 | 业务库名 | 默认 `canteen_verify` | — |
| `DB_SYNC` | ★ | 表结构自动同步开关：1=启动时按代码实体自动建表加列；0=关闭 | **生产必须 0**（自动同步有误删列/改类型风险） | =0 时改了代码实体必须手工执行迁移 SQL（线上曾因漏执行导致员工登录 1003） |
| `DB_HOST` / `DB_PORT` | 免改 | 后端连库地址 | 编排内固定为服务名 `mysql`，不要改 | — |

### 2. 端口（宿主机侧，全部只绑 127.0.0.1 不暴露公网）

| 变量 | 标记 | 默认 | 说明 |
|---|---|---|---|
| `MYSQL_HOST_PORT` | ◇ | 3307 | 仅宿主机本机调试用；公网访问走 443，与此无关。被占用才需换 |
| `REDIS_HOST_PORT` | ◇ | 6380 | 同上 |
| `API_HOST_PORT` | ◇ | 3100 | 同上（nginx 反代指向它） |

### 3. 登录密钥（JWT）

| 变量 | 标记 | 是什么 | 怎么配 | 改动影响 |
|---|---|---|---|---|
| `JWT_SECRET` | ★ | 登录 token 的签名密钥，泄露=任何人可伪造登录 | 服务器执行 `openssl rand -hex 32` 粘贴输出 | ⚠️ 更换后**所有已登录用户立即掉线** |
| `JWT_EXPIRES_IN` | ◇ | token 有效期（`s/m/h/d`） | 默认 `7d`；想更严用 `1d` | 改短后员工需更频繁重登 |

### 4. 核销码

| 变量 | 标记 | 是什么 | 怎么配 |
|---|---|---|---|
| `QRCODE_TTL` | ◇ | 动态核销码有效期（秒），小程序页显示的「5 分钟内有效」就是它 | 默认 300；调短更安全但员工来不及出示，**别低于 120** |

### 5. 微信小程序

| 变量 | 标记 | 是什么 | 从哪来 | 改动影响 |
|---|---|---|---|---|
| `WX_APPID` | 免改 | 小程序身份证号 | mp.weixin.qq.com → 开发设置页顶部 | — |
| `WECHAT_APPSECRET` | ★ | 后端调微信 `code2session` 换用户身份的密钥 | 同页「生成/重置」（只显示一次，当场复制） | ⚠️ 微信后台重置后旧值立即失效，必须同步改这里并 `docker compose restart api` |

> 未配置这两个值时后端自动降级为 **mock openid 通道**（日志会警告），员工用假身份登录——只限本地开发。

### 6. 设备与杂项

| 变量 | 标记 | 是什么 | 怎么配 |
|---|---|---|---|
| `ALLOW_LEGACY_DEVICE_TOKEN` | ◇ | 1=允许旧版扫码 App 用明文设备密钥直连；0=一律走新绑定流程 | 所有设备装了 v1.1.0+ App 就保持 0（更安全）。**本地模式自动放开** |
| `TZ` | 免改 | 时区，影响日志与核销时段判断 | `Asia/Shanghai` |
| `DOMAIN` | ◇ | 一键部署脚本 `deploy.sh` 给这个域名签 HTTPS 证书 | 换域名时改这里 + 域名 A 记录 + nginx 同步 |

### 7. 仅本地开发用（生产不出现）

| 变量 | 是什么 |
|---|---|
| `LOCAL_MODE=1` | 零依赖模式：SQLite(WASM) 代替 MySQL、跳过 Redis，`npm start` 即跑 |
| `PORT` / `HOST` | 本地监听端口/地址（默认 3000 / 0.0.0.0） |
| `REDIS_HOST` / `REDIS_PORT` | 非编排环境手动指定 Redis |

> 优先级：环境变量 > `.env` 文件（pm2/docker 注入的值覆盖文件里的）。

| 位置 | 配置 | 当前值 | 何时改 |
|---|---|---|---|
| `miniprogram/utils/request.js` → `BASE_URL` | 后端接口地址 | `https://tuancan.gengle.xyz` | 换服务器/域名时 |
| `miniprogram/project.config.json` → `appid` | 小程序 ID | `wx7ac65adc8cc002de` | 换小程序主体时 |
| 微信后台 → 开发设置 → 服务器域名 → request 合法域名 | 域名白名单 | `https://tuancan.gengle.xyz` | 跟随 BASE_URL；**不配真机必报「网络异常」** |

注意：
- 开发者工具调试可勾「不校验合法域名」省事，**真机/体验版必须配白名单**
- 正式版要求域名 ICP 备案（`gengle.xyz` 已备案 ✅）
- 微信后台域名「每月可改 5 次」，一次填对

### 2. 扫码 App（Android）

| 位置 | 配置 | 当前值 | 何时改 |
|---|---|---|---|
| `app/build.gradle.kts` → `buildConfigField API_BASE` | 后端地址（编译期写死） | `https://tuancan.gengle.xyz` | 换服务器后**必须重新编译 APK** |
| `app/src/main/res/xml/network_security_config.xml` | 明文流量策略 | 已收紧（禁止 HTTP 明文，全走 TLS） | 已是最终态，不要放开 |

改完地址后重新编译：
```bash
cd scan-app-android
gradle assembleRelease   # 产物 app/build/outputs/apk/release/
```

### 3. 管理后台

无任何配置文件。前端所有请求用相对路径 `/api/...`，浏览器访问哪个域名就请求哪个域名，**换域名零改动**。

### 4. 服务器 / nginx

| 位置 | 内容 | 操作方式 |
|---|---|---|
| `/opt/canteen/nginx.conf` | 反代规则、HTTPS server 块、ACME 续期路径 | 改完执行 `docker exec canteen-web nginx -s reload` |
| `/etc/letsencrypt/`（容器只读挂载） | Let's Encrypt 证书 | 90 天自动续期；异常时重跑 `sudo bash /opt/canteen/enable-https.sh tuancan.gengle.xyz` |
| `/opt/canteen/backend/.env` | 旧部署（pm2 模式）的后端配置 | 与 `deploy/.env` 同一套变量；切 Compose 编排后以 `deploy/.env` 为准 |

## 四、常见配置变更操作

### 改数据库密码
1. 进容器改真实密码：`docker exec -it canteen-mysql mysql -uroot -p -e "ALTER USER 'canteen'@'%' IDENTIFIED BY '新密码';"`
2. 同步改 `deploy/.env` 的 `DB_PASSWORD`
3. 重启后端：`docker compose restart api`

### 重置微信 AppSecret
1. mp.weixin.qq.com → 开发设置 → 重置 AppSecret（旧值立即失效）
2. 改 `deploy/.env` 的 `WECHAT_APPSECRET`
3. 立即 `docker compose restart api`（间隔期间员工登录会失败）

### 换域名
1. 域名控制台加 A 记录指向服务器 IP，等解析生效
2. `deploy/.env` 改 `DOMAIN`；小程序 `request.js` 改 `BASE_URL`；扫码 App 改 `API_BASE` 并重新编译
3. 重跑 `sudo bash /opt/canteen/enable-https.sh 新域名` 签新证书
4. 微信后台服务器域名更新为新域名（注意每月 5 次限制）

### 调核销码有效期
改 `QRCODE_TTL` 后 `docker compose restart api` 即可，**只影响新签发的码**。

### 加表结构变更（DB_SYNC=0 时）
改了后端实体后必须写迁移 SQL 并在库上执行，再发新代码——顺序反了会直接报「Unknown column」。
参考教训：`token_version` 列缺失导致员工登录 1003（2026-09-24）。

## 五、安全红线

1. **`deploy/.env` 永远不进 git、不发群、不截图**（.gitignore 已排除，别手滑 `git add -f`）
2. **`scan-app-android/keystore/` 是签名密钥**，泄露=任何人可冒签你的 App，同样不进 git
3. `JWT_SECRET` 泄露立即换（代价是全员重新登录）
4. AppSecret 在微信后台有泄露疑虑就重置，重置后同步 `.env` + 重启
